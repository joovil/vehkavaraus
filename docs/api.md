# API reference

> **Note:** This documentation was generated by Claude Opus 5.5 (Anthropic) based on the project source code.

All routes are Next.js route handlers in `src/app/api/`. Client code should call them through the wrappers in `src/lib/services/` (see [conventions.md](../conventions.md)).

- Authentication uses the next-auth session cookie.
- Errors are returned as JSON `{ "error": "<message>" }`, except where noted.
- A Bruno collection with example requests is in [`brunoRequestCollection/`](../brunoRequestCollection).

## Summary

| Method   | Path                              | Auth                     | Description                          |
| -------- | --------------------------------- | ------------------------ | ------------------------------------ |
| GET/POST | `/api/auth/[...nextauth]`         | –                        | next-auth handler (login, session)   |
| POST     | `/api/signup`                     | –                        | Create a user                        |
| GET      | `/api/auth/verification/[id]`     | –                        | Verify email with key                |
| POST     | `/api/auth/verification`          | session                  | Resend verification email            |
| PUT      | `/api/users`                      | session                  | Update own apartment and/or password |
| GET      | `/api/games`                      | –                        | List all games                       |
| GET      | `/api/games/[id]`                 | –                        | Get one game                         |
| POST     | `/api/borrows`                    | session                  | Borrow a game                        |
| POST     | `/api/borrows/return/[id]`        | session (owner or admin) | Return a borrow                      |
| GET      | `/api/admin/games`                | admin\*                  | Games with current borrow and borrower |
| POST     | `/api/admin/games`                | admin\*                  | Add a game with an image             |
| DELETE   | `/api/admin/games/[id]`           | admin\*                  | Delete a game and its image          |
| GET      | `/api/cron/late-check`            | `Bearer CRON_SECRET`     | Mark overdue games as `late`         |
| GET      | `/api/test`                       | –                        | Debug route (redirects to `/games`)  |

\* Admin route handlers check for the `admin` role themselves and return `401` otherwise. The middleware matcher skips `/api`, so it does not protect these routes.

## Auth & users

### `POST /api/signup`

Body (JSON):

```json
{ "username": "matti", "password": "secret", "email": "matti@example.com", "apartment": "A12" }
```

- The input is validated with zod. `apartment` must match `^[abAB]\d{1,3}$`. The user is created with the role `unverified` and a verification email is sent.
- `200` `{ "message": "User created successfully" }`
- `400` if fields are missing, validation fails or the username is too short
- `409` if the username is already in use. Because of a bug, any other database error also returns 409 (see [Known issues](setup.md#known-issues)).

### `GET /api/auth/verification/[id]`

`[id]` is the verification key (UUID) from the email. The key is marked used and the user's role becomes `user`.

- `200` `{ "message": "User verified" }`
- `400` if the key is unknown or already used (`"Key expired"`)

### `POST /api/auth/verification`

Deletes the logged-in user's old verification key and sends a new email.

- `200` `{ "message": "New verification email sent" }`
- `401` if not logged in

### `PUT /api/users`

Body (JSON), at least one field required:

```json
{ "apartment": "B3", "password": "newSecret" }
```

- `200` the updated user (client-safe fields only)
- `400` if fields are missing or invalid
- `401` if not logged in

## Games

### `GET /api/games`

Returns an array of games: `id`, `name`, `borrowStatus`, `availableDate`, `imageUrl`, `currentBorrow`.

### `GET /api/games/[id]`

- `200` one game
- `400` `{ "message": "Game not found" }`

## Borrows

### `POST /api/borrows`

Body: `{ "gameId": 1 }`. Creates a borrow for the logged-in user with a due date one week ahead.

- `201` the created borrow
- `400` if `gameId` is missing or the game is not `free`
- `401` if not logged in
- `403` if the user is `unverified`

### `POST /api/borrows/return/[id]`

`[id]` is the borrow id. Sets `returnDate` and marks the game `free`.

- `200` `{ "message": "Game returned" }`
- `401` if not logged in
- `403` if the borrow belongs to another user and the caller is not an admin

## Admin

### `GET /api/admin/games`

Returns all games joined with their current borrow and borrower. Each item has these fields: `gameId`, `gameName`, `borrowStatus`, `imageUrl`, `borrowId`, `borrowDate`, `dueDate`, `username` and `apartment`. The admin panel uses this.

### `POST /api/admin/games`

`multipart/form-data` with these fields:

- `name`: the game name
- `file`: the image

The image is uploaded to Vercel Blob as `vehka/games/<name>` (requires `BLOB_READ_WRITE_TOKEN`) and the game is created.

- `200` the created game
- `400` `{ "error": "Game already added" }`
- `404` `{ "message": "not implemented" }` on any other error

### `DELETE /api/admin/games/[id]`

Deletes the game row and its blob image.

- `200` `{ "message": "Game deleted successfully" }` or `{ "message": "Game already deleted" }`
- On error: `{ "error": ... }` with status 200

## Cron

### `GET /api/cron/late-check`

Requires the header `Authorization: Bearer <CRON_SECRET>`. Vercel calls it daily at 08:00 UTC (see `vercel.json`).

- `200` `{ "success": true }`
- `401` if the header is invalid
- `500` on an internal error

Run it locally:

```bash
curl -H "Authorization: Bearer secret" http://localhost:3000/api/cron/late-check
```
