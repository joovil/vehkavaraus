## About the project

Vehkavaraus is a website created for the tenants of Vehkapolku to mark and track the borrows of communal board games. Users are required to verify their emails before any borrows can be made.

Admin tools are included to add new games or to make changes to the status of borrowed games if needed.

Images are stored on a Vercel blob and new images are compressed on the client side before being sent to the blob. The PostgreSQL database is hosted on Neon and Kysely is used to query the data.

The site is hosted on Vercel: [vehkavaraus.joovil.dev](https://vehkavaraus.joovil.dev)

## Features

#### Tenants

- Sign up with username, password, email and apartment (format `A12` / `B3`: letter A or B followed by 1–3 digits)
- Email verification via a link sent with Resend; unverified users can request a new email
- Browse all games and see when a borrowed game becomes available again
- Borrow a game (default loan period: 1 week) and return it from the user page
- Change apartment and password from the user page

#### Admins (users with the `admin` role)

- Admin panel (`/admin/admin-panel`) listing all games with status (free / borrowed / late), borrower apartment and dates
- View the borrow history of a game, force-return a borrow, delete a game
- Add new games with an image (`/admin/add-game`)

#### Automation

- A daily Vercel cron job (`/api/cron/late-check`, 08:00 UTC) marks overdue borrows as `late`

## Quick start

### Prerequisites

- Node.js 26 (Node 24 also works for installing, running and testing, but pnpm prints an engine warning)
- [pnpm](https://pnpm.io/) 9 (`corepack enable` picks up the version pinned in `package.json`)
- Docker with the Compose plugin (`docker compose`, v2)

### 1. Install dependencies

```bash
pnpm install
```

### 2. Start the development database

```bash
pnpm devdb
```

This starts PostgreSQL 17 in the background in the container `vehkavaraus_db` on port `5432`. On first start `database/init.sql` creates the `vehka` database. Data is persisted in `database/data/` (gitignored).

### 3. Configure environment variables

`.env.development` is committed and contains the local database and auth settings. Add secrets that are not committed to `.env.development.local` (gitignored):

```bash
# Optional: a real key makes verification emails actually send
RESEND_API_KEY=re_xxx
# Optional: needed only for adding and deleting games (image upload)
BLOB_READ_WRITE_TOKEN=vercel_blob_rw_xxx
```

The app works without these. `.env.development` has a placeholder `RESEND_API_KEY`, so signup succeeds but no email is sent (see [verifying a user without email](#verifying-a-user-without-email)).

See [docs/setup.md](docs/setup.md#environment-variables) for the full list.

### 4. Run migrations

```bash
pnpm migrate:dev
```

### 5. (Optional) Seed games

```bash
docker exec -i vehkavaraus_db psql -U postgres -d vehka < database/add_games.sql
```

### 6. Start the app

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000). The root path redirects to `/games`.

### 7. Make yourself an admin

There is no UI for granting roles. After signing up, promote your user in SQL:

```bash
pnpm enterdb
```

```sql
\c vehka
UPDATE users SET role = 'admin' WHERE username = 'your_username';
```

Log out and back in so the new role is stored in your session. In development (`NODE_ENV=development`) the admin pages are not access-protected by the middleware, but the admin API routes always require the `admin` role.

### Verifying a user without email

With the placeholder Resend key, nobody receives the verification link. Verify the user by hand after signing up (replace `your_username`):

```bash
docker exec vehkavaraus_db psql -U postgres -d vehka -c \
  "UPDATE users SET role = 'user' WHERE username = 'your_username'"
```

Then log out and back in. Unverified users can browse games but cannot borrow.

## Running the tests

The tests run against a separate PostgreSQL container on port `5433`. They empty the `borrows`, `games`, `verifications` and `users` tables before running, so only point them at a test database.

```bash
pnpm testdb         # start the test database
pnpm migrate:test   # create the tables in it
pnpm vitest run     # run all tests once (`pnpm test` runs in watch mode)
```

Other checks: `pnpm lint` and `pnpm checkTypes`. `pnpm build` needs the production environment variables (database, Resend, API URL), so it won't succeed on a plain checkout.
